ARCHITECTURE / SOFTWARE-VISIBLE MODEL

One hart,
clear boundaries.

The family is a cacheless RV32 microcontroller platform with directly addressed local memory, one machine-mode interrupt context, and a single JTAG debug target.

Execution
In-order RV32 little-endian hart
Common services
CLINT, PLIC, Debug 1.0 Minimal, Zicntr and Zihpm
Memory rule
No cache, cacheable alias, or cache-maintenance contract
Reading rule. This is the single family-level location for the ISA/ABI declaration, software-visible address map, and PLIC source allocation. For product-specific behavior, use the M0 Profile, M1 Profile, or M2 Profile. Register-level behavior remains owned by the product architecture and peripheral specifications.

01 / CORE AND PRIVILEGE

Use the product ISA and ABI declaration exactly.

All products share C, CSR, fence.i, counter, HPM, and pause contracts. M1 and M2 add RV32M, U-mode, and PMP; M2 additionally adds RV32F, standard B, and Zcf. U-mode counter access on M1 and M2 is controlled by mcounteren.

Traps

Machine mode owns trap vector installation, exception handling, local and external interrupt enable, and return through mret.

WFI

WFI is an architectural wait, not a clock-gating API. Wake and pending-interrupt behavior are part of the clock/reset and interrupt contracts.

Debug

Debug is a single-hart Debug 1.0 Minimal JTAG DTM/DMI target. RTL coverage does not by itself establish physical-board debugger interoperability.

02 / MEMORY AND ORDERING

Local TCM is deterministic; product extensions use the same map.

ITCM is executable local SRAM. DTCM is non-executable local data SRAM. A DBus patch to instruction memory requires fence.i before execution observes modified instructions.

The complete sparse map below is the product-manual view of the address-space contract. Reserved means CPU-unmapped and bus-faulting until a product explicitly implements the window.

Local-memory execution

Direct CPU TCM accesses do not traverse a shared-memory arbitration fabric. Product-specific capacity and extension behavior is defined by the corresponding Preliminary Product Datasheet.

Ordering rule

No product supplies a data cache, DMA coherency fabric, or cache-maintenance operation. Software establishes ownership before a DMA transfer and consumes status/interrupt completion before reusing the buffer.

03 / INTERRUPTS, COUNTERS, AND DEBUG

One interrupt vocabulary across the family.

CLINT supplies MSIP, MTIP, and platform time. The PLIC supplies MEIP from 32 global sources through one machine-mode context with 3-bit priorities. The source map below is the shared family ABI; a product wires only its implemented sources.

  1. Source ID 0 is reserved and never represents an interrupt.
  2. A source is eligible only when pending, enabled, not in service, and strictly above threshold.
  3. The highest priority source wins; equal priority resolves to the lowest source ID.
  4. Firmware clears the device condition before completing the claimed source when a single service instance is intended.
PLIC

Claim and complete

Firmware enables the peripheral locally, configures source priority/enable/threshold, claims the selected ID, clears its device condition, then completes the same ID.

SOURCES

Family source ABI

Implemented sources are fixed. Reserved IDs remain tied low until their RTL, software ABI, and directed test are integrated.

HPM

Four programmable counters

HPM3–HPM6 are the implemented family subset, in addition to cycle, time, and instret. HPM7–HPM31 must not be advertised.

JTAG

Minimal transport

DTM/DMI, one Debug Module, GPR and debug-CSR access, halt/resume, and system-bus access form the documented RTL target boundary.

04 / RESET, BOOT, AND ERROR RESPONSE

Boot evidence is distinct from a production boot-policy claim.

The SoC testbench exercises bypass, JTAG/DMI, UART, and SPI-slave loading paths. Product firmware starts from its linker-defined boot address, installs its trap entry, initializes data, and establishes interrupt policy.

Firmware image

The BSP emits separate instruction and data images. Image generation verifies that loadable bytes are inside the selected product memory regions.

Bus errors

Unmapped or denied accesses return a defined bus-error response to the core. M1 and M2 PMP policy applies to CPU fetch, loads, and stores.

Board boundary

Physical reset sequencing, pin assignment, loader transport qualification, and an externally programmable image format remain board bring-up work.
