01 / CONTROLLED FEATURE SWEEP

One clean revision. Five cumulative gates.

Every point was rebuilt from the same pre-public clean engineering baseline with the same product-local image, -O2 -falign-functions=4 -falign-loops=4 -falign-jumps=4, linker layout, and Verilator run. Gates are added in order: early local-load, load-response bypass, BHT, RAS, then upper-32 prefetch. 03 / PROFILE RESPONSE BY FEATURE GATE

The largest gains remove deterministic memory waiting.

D-bus wait, load-use stalls, and redirect observations can overlap; only raw-cycle deltas are additive performance evidence.

Memory launch

Early local-load removes 140–143k cycles. D-bus wait falls from 112k to 8k; load-use declines from 96–98k to 49–51k.

Dependency response

Load-response bypass removes a further 48–51k cycles and leaves only 1k load-use stalls in each profile window.

Control response

BHT is image-sensitive: M0 pays 3k cycles, while M1/M2 recover about 7k. RAS then removes 9–10k; U32 prefetch contributes 2–5k.

04 / ENGINEERING INTERPRETATION

The largest wins removed deterministic waiting.

Local-memory path

Early local-load moves accepted local SRAM reads ahead of the normal MEM-stage launch without making the core decode the SoC address map.

Control flow

The small BHT has modest workload value. A four-entry RAS is more effective for ABI returns because their targets are highly predictable.

Dependency path

Completed-load response bypass removes the immediate load-consumer interlock; it delivers the largest late-stage incremental cycle recovery.
