This is the executable evidence plan for physical VCU108 validation. M0 UART boot has one retained end-to-end smoke record; it does not qualify the remaining board, adapter, or debugger paths.

Transport

Prerequisite. Routed timing evidence is necessary but not sufficient. The M0 UART smoke record is available below; do not label a product board-ready until every applicable item in this guide has a retained command transcript and observed result.

CURRENT BOARD EVIDENCE

M0 has completed the first visible firmware smoke.

Open the M0 UART boot to Hello World record for the complete build chain, serial protocol, physical routing, host transcript, and scope boundary.

01 / PREPARE A RECORD

Capture the immutable inputs before programming.

02 / BASIC BOARD BRING-UP

Establish clock, reset, and visible firmware execution first.

  1. Program and identifyProgram the bitstream, record the programming output, and confirm the expected FPGA device and board revision.
  2. Reset and clockObserve clock lock and reset release with the product’s intended constraints and image. Record reset cause or failure symptoms.
  3. UART and GPIORun a reproducible BSP image, capture the complete UART stream, and record GPIO pass signaling against documented physical pin mapping.
  4. Interrupt smokeExercise a timer/PLIC path and watchdog pre-timeout path with an observable completion result.

03 / JTAG AND DEBUG

Prove the transport before claiming source-level debug.

Adapter and target configuration files must be versioned with the evidence record. A successful scan alone does not establish DMI access, halt control, or recovery behavior.

SCAN

Chain discovery

Record the expected chain and IDCODE/DTM discovery result, cable configuration, and recovery after a transport reset.

DMI

Debug Module access

Exercise dmactive, halt/resume, GPR access, debug CSRs, and a bounded system-bus memory access.

GDB

Source-level session

Archive a scripted halt, register read, breakpoint or single-step, memory read, resume, and reset-recovery transcript.

INTERACTION

Architectural edges

Record behavior across WFI, traps, reset, and—on M1/M2—PMP/U-mode boundaries before asserting debugger support.

04 / PRODUCT-SPECIFIC SMOKE

Use an observable path for each product addition.

M0

Boot, UART, GPIO, timer, PLIC, watchdog, and recovery after debug reset.

M1

U-mode/PMP boundary, expected fault behavior, and debug interaction without weakening the protected execution test.

M2

FP arithmetic, System SRAM banking, DMA descriptor copy, UART0 TX DMA, and an intentional firewall/error path.

05 / ARCHIVE AND DISPOSITION

One run is useful only if another engineer can reproduce it.

Required artifacts

Bitstream hash, constraints, board revision, host and tool versions, adapter configuration, complete command transcript, UART log, and debugger log.

Observed result

Store expected and observed outputs together, including screenshot/waveform evidence only as supporting artifacts rather than the sole result.

Known deviations

Record failures and limitations with a stable ID, product/revision scope, workaround, and planned disposition.
