VERIFICATION AND EVIDENCE

Evidence is
scope-bound.

The eRISCV documentation distinguishes architecture conformance, directed SoC behavior, software execution, routed FPGA implementation, and physical-board validation.

Default regression simulator
Verilator
Focused debug and waveforms
ModelSim through the WSL wrapper
Source of dated totals
MCU Evidence Snapshot
Publication boundary. A passing simulation or positive routed timing result is engineering evidence. It is not a certification, availability, safety, power, frequency, package, or board-validation statement.

01 / EVIDENCE STACK

Use the right test for the claim.

01

Architecture and ACT

Core tests exercise the declared instruction and privilege contract. ACT4 is core-TB evidence, not boot-transport or full-system evidence.

02

Directed SoC

Directed tests cover memory mapping, boot paths, peripherals, CLINT/PLIC, debug, PMP, and M2 TCM/DMA integration boundaries.

03

Software workloads

BSP, RTOS, benchmark, and M2 FP/DMA workloads demonstrate a bounded build and execution path with a declared oracle.

04

Implementation and board

Routed FPGA reports establish a device/tool/configuration timing snapshot. Board programming, I/O, JTAG, and debugger evidence are separate.

03 / STATIC RTL CHECKS

Screen structure before simulation.

These commands run the repository Verilator lint flow over the selected product RTL. They are a structural screen for latches, multiple drivers, unused logic, and compatibility diagnostics; they do not establish functional or timing closure.

One product

make lint LINT_PRODUCT=m0
make lint LINT_PRODUCT=m1
make lint LINT_PRODUCT=m2

One RTL boundary

make lint LINT_PRODUCT=m2 \
  LINT_TARGET=core
make lint LINT_PRODUCT=m2 \
  LINT_TARGET=soc

All products

make lint-all

# convenience aliases
make lint-m0
make lint-m1
make lint-m2

04 / REGRESSION

Start broad, then narrow.

Verilator is the default regression simulator. A product full target is the normal closure entry point; it runs core-directed tests, the product ACT4 selection, and SoC-directed tests. 07 / RELEASE AND BOARD GATES

What remains outside current engineering closure.

Physical hardware

Bitstream programming, reset release, UART/GPIO observation, JTAG scan, OpenOCD/GDB sessions, and board-specific I/O timing require archived board evidence.

Product release

A dated release package requires versioned RTL, build inputs, known deviations, and the intended support/compatibility statement.

Commercial data

Package, electrical limits, power, reliability, lifecycle, orderable part numbers, and guaranteed frequency are unpublished.

Security and safety

PMP and U-mode tests do not constitute a security certification. No safety-integrity claim is made.

Performance

Use the published methodology and exact conditions for any benchmark result. Do not convert a functional workload into a general throughput promise.

Errata

Record a stable ID, affected revision, observable symptom, workaround, and disposition before publishing a correction.
