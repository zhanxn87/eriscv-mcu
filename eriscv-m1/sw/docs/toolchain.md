# eRISCV-M1 BSP Toolchain Contract

This is the frozen v0.1.0 build contract for the M1 BSP. A compatible build
must use the settings below; changing ISA, ABI, memory layout, or image format
creates a different BSP compatibility target.

| Item | Contract |
|---|---|
| Compiler prefix | `riscv64-unknown-elf-` |
| ISA | `rv32imc_zicsr_zifencei_zicntr_zihpm_zihintpause` |
| Bare-metal ABI | `ilp32` |
| RTOS ABI | `ilp32` (`RTOS_ABI`) |
| Code model | `medany` |
| Runtime | freestanding; `-nostdlib -nostartfiles` (M extension supplies multiply/divide) |
| Linker script | `linker/eriscv_mcu.ld` |
| ITCM | 64 KiB at `0x1000_0000` |
| DTCM | 64 KiB at `0x1100_0000` |
| BSP boot address | `ERISCV_MCU_BOOT_ADDR` (`0x1000_0000`, ITCM base) |
| Images | `<example>.imem.mem`, `<example>.dmem.mem` generated by `tools/elf_to_mem.py` |
| Default regression simulator | Verilator |

## Reproducible commands

```bash
make -C eriscv-m1/sw images-all
make -C eriscv-m1/sw ci
make -C eriscv-m1/sw sim-coremark
```

The frozen CI suite is `hello_uart`, `timer_apb_poll`, `timer_clint`,
`wfi_tickless`, `irq_timer_uart`, and `wdt_smoke`. `async_uart` remains a
non-frozen experimental example and is not part of the v0.1.0 compatibility
contract.

## Compatibility rules

- `isa.mk` is the authoritative compiler contract. Bare-metal targets expose
  overridable `ISA` and `ABI` variables; RTOS targets use `RTOS_ABI`.
- Application objects must compile with the ISA and ABI above.
- Applications may use only the API in `include/eriscv_mcu.h` and addresses in
  `include/eriscv_mcu_config.h`.
- `ERISCV_MCU_BOOT_ADDR` and the linker `__eriscv_mcu_*` region symbols are the
  published BSP memory-map contract. Simulation runners take `boot_addr` from
  the linked ELF entry point; they do not carry a separate address setting.
- The simulator consumes the generated memory images, not an ELF directly.
- M1 retains its M extension and PMP configuration; neither changes this BSP
  build contract.
- Verilator is the default regression backend. Use ModelSim for focused
  debugging and waveform inspection; neither simulator replaces FPGA or board evidence.

The CoreMark smoke is a separate M1 benchmark target. It uses pinned CoreMark
v1.01, one validation iteration, and `mcycle`; its ModelSim cycle result is
not an official CoreMark score because it does not satisfy the upstream
10-second reporting rule.
